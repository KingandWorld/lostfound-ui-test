## 一、设计目标

1. 对后端全部核心接口建立**自动化契约回归**——接口文档（v3.3）与真实后端逐条对账，防止迭代引入接口回归；
2. 覆盖**协议层 + 数据层**：除业务接口外，通过 SSH 隧道直连真实数据库做数据校验；
3. 接入 **Jenkins CI**，代码变更自动触发回归（Poll SCM 30 分钟，CI 模式守卫）。

## 二、技术栈与结构

| 项 | 选型 |
|----|------|
| 语言/框架 | Python + pytest |
| 请求层 | requests（统一 Session / Token 管理） |
| 报告 | allure-pytest（Allure 2.x） |
| 数据驱动 | JSON 用例数据文件（参数化） |
| 数据校验 | pymysql（SSH 隧道连真实库） |
| CI | Jenkins 自由风格任务（CI 模式守卫 + Poll SCM） |

```
lostfound-api-test/
├── testcases/            # 55 条用例（6 个模块）
├── config/               # settings + 环境配置
├── utils/
│   ├── api_client.py     # 统一请求封装（认证/日志/断言）
│   ├── db_utils.py       # 数据库校验工具（SSH 隧道）
│   ├── ci_guard.py       # CI 模式守卫（本地全量 vs CI 冒烟）
│   └── allure_helper.py  # Allure 步骤/标签封装
├── conftest.py           # fixture：token / 清理 / 报告
└── pytest.ini            # 标记 + Allure 配置
```

## 三、用例设计（55 条）

| 模块 | 用例数 | 覆盖点 |
|:----:|:---:|--------|
| 认证 | 12 | 登录成功/失败、连续失败锁定策略（5 次锁定 15 分钟、成功重置）、Token 生成与校验、注册-审核流 |
| 物品 | 20 | 发布/编辑/删除/查询 CRUD、分页搜索、状态流转（待认领→待审核→已认领）、图片上传、越权拦截 |
| 搜索 | 10 | 关键词/模糊/组合搜索、分类筛选、分页排序、空结果、特殊字符 |
| 认领 | 5 | 提交申请、取消、审核通过/拒绝、状态同步 |
| 数据库校验 | 4 | 发布后落库核对、状态变更落库核对、数据一致性（操作前后对比） |
| 端到端 | 4 | 注册→审核→登录→发布→搜索→认领 全链路协议层验证 |

**设计要点：**

- **数据驱动**：认证/搜索类用例的输入与预期从 JSON 数据文件读取，参数化执行——新增数据不写代码；
- **契约对账**：API 文档 v3.3 与真实后端逐条核对（响应结构、错误码、字段约束），发现文档与实现不一致处以实测为准并记录；
- **双通道验证**：同一功能协议层（接口用例）+ 表现层（UI 用例）双重验证，共用同一测试账号；
- **状态管理**：共享 Token fixture，认证用例失败时快速失败（不串行污染其他用例）。

## 四、CI 集成设计

| 项 | 设计 |
|----|------|
| 触发方式 | Jenkins Poll SCM 30 分钟（代码变更自动构建） |
| CI 模式守卫 | 本地默认全量 55 条；CI 环境走冒烟子集（认证 + 端到端），控制构建时长 |
| 失败策略 | 断言失败即失败；环境性超时由重试机制兜底（pytest-rerunfailures） |
| 报告 | Allure 生成 → 归档，与外网报告体系打通（见 `CI-CD流水线设计.md`） |
| 凭据 | 测试账号/COS 凭据走 Jenkins 凭据管理，仓库零硬编码 |

## 六、卡点与解法（工程经验沉淀）

| 卡点 | 现象 | 解法 |
|------|------|------|
| 账号锁定契约 | 连续失败 5 次锁定 15 分钟 | 错误密码用例放最后执行 + 宽断言（不因环境顺序失败） |
| 数据库不可远程直连 | 服务器 MySQL 仅监听本机 | SSH 隧道方案：本地 `13306` 映射服务器 `3306`，隧道不通时用例自动跳过（学习模式降级） |
| 环境性超时 | 端到端用例偶发超时 | rerunfailures 重试（仅重试超时/网络类，断言失败不重试） |
| 依赖安装 | 清华源缺包/403 | 官方 PyPI + `NO_PROXY=*`，或阿里云镜像 |
