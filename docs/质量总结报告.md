## 三、平台级卡点复盘（工程经验）

| # | 卡点 | 根因 | 解法 | 影响面 |
|:-:|------|------|------|--------|
| 1 | COS 上传复核 MISMATCH（桶内 114 vs 预期 74） | Allure 附件随机 UUID 文件名 + `put_object` 只增不删 → 孤儿对象堆积 | `--prune` 幂等清理（dry-run → 真删 → 复核 74=74 OK） | 报告归档一致性 |
| 2 | COS SDK 分页 `SignatureDoesNotMatch(403)` | `IsTruncated` 是字符串 `"false"`（真值）+ 翻页 marker 为 None 被 requests 丢弃 | `== "true"` 显式比较 + `or ""` 兜底 | 批量清理/上传脚本 |
| 3 | Jenkins 容器 OOM | 768MiB 内跑浏览器必被杀（cgroup 内核日志实证） | 内存放大至 1024MiB + 冒烟/全量两档升级路径 | CI 稳定性 |
| 4 | 容器时区 UTC | cron 按容器时区执行 | `H 18 * * *`（=北京 02:00），改时区需同步改 cron | 定时构建 |
| 5 | 报告外链 NXDOMAIN | 计划文档报告域名公网 DNS 不存在 + `COS_CDN_DOMAIN` 未配 | 方案B：服务器 nginx `/r/` 托管（流量走免费包，零新增成本） | 报告可访问性 |
| 6 | 邮件通知 503 | SMTP 认证未配置（网络层 587 已通） | 配置 Extended 段认证（Jenkinsfile `emailext` 使用段） | 失败通知 |

## 四、质量结论

1. **功能质量**：v1.0 首轮 85.7% → 两轮修复后 100%，核心业务流程（注册 → 审核 → 登录 → 发布 → 搜索 → 认领）验证通过；
2. **自动化体系**：接口 55 条 + UI 21 条形成协议层/表现层双重回归防线，接口 CI 全自动、UI 本地一键 + 服务器冒烟双通道；
3. **工程闭环**：CI/CD 端到端 ≈30s，报告自动发布外网可访问，每日定时构建产出质量看板；
4. **遗留项明确**：2 个前端缺陷（注册契约 / 认领池）有定论、有复测路径，修复后自动恢复对应用例；
5. **数据纪律**：本报告全部数字可溯源（用例数 → 禅道/仓库 README、基线 → 测试运行报告、行数 → 实测），面试与复盘可直接引用。
