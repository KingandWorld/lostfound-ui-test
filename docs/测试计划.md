## 一、测试目标

验证失物招领系统（前后端分离 Web 应用）的核心功能正确性与可靠性，并建立可持续的自动化回归与 CI/CD 质量保障体系：

1. **功能层面**：验证失物/招领发布、认领审核、物品状态流转等核心流程符合需求与设计规范；
2. **接口层面**：对后端 API 建立自动化契约回归，防止迭代引入接口回归；
3. **UI 层面**：对核心用户流程建立端到端自动化，保障发布质量；
4. **工程层面**：搭建 Jenkins 流水线 + Allure 报告 + 外网可访问的质量看板。

### 2.2 自动化测试范围

| 层 | 范围 | 说明 |
|----|------|------|
| 接口自动化 | 认证 / 物品 / 搜索 / 认领 / 数据库校验 / 端到端 | 55 条用例，覆盖协议层全部核心接口 |
| UI 自动化 | 登录 / 发布 / 搜索 / 注册 / 认领 | 21 条用例，覆盖核心用户流程 |

### 2.3 不在本次范围

- 性能/负载/压力测试（建议独立轮次）；
- 完整兼容性矩阵（本次以 Chrome 为主，Chrome + Edge 抽查）；
- 渗透测试（本次仅覆盖基础 XSS / SQL 注入 / 越权用例）。

## 三、测试策略

| 测试类型 | 方法 | 覆盖要求 |
|---------|------|---------|
| 功能测试 | 黑盒手工执行，逐条验证 | P0 用例 100% 执行，P1 ≥ 90% |
| 接口自动化 | pytest + requests + Allure，数据驱动 | 核心接口 100% 覆盖，接入 CI 自动回归 |
| UI 自动化 | Playwright + Page Object，失败自动截图 | 核心流程端到端覆盖，本地一键运行 |
| 安全用例 | XSS / SQL 注入 / 越权访问检测 | 注册、搜索等输入类模块必测 |
| 异常场景 | 断网 / Session 过期 / 重复提交 / 多标签页 | 关键流程必测 |
| 数据验证 | 操作前后查数据库对比（SSH 隧道连真实库） | 增删改类用例必做 |
| 回归测试 | Bug 修复后逐项验证 + 自动化全量基线 | 每轮修复闭环 |

## 四、测试环境

| 项 | 配置 |
|----|------|
| 操作系统 | Windows 11（本地测试） |
| 浏览器 | Chrome 最新稳定版（UI 自动化 headless 同版本内核） |
| 内存限制 | 4GB 模拟低配用户环境 |
| 被测系统 | 失物招领系统（生产环境直测，破坏性操作后立即恢复数据，专用测试账号） |
| 服务器 | 4G 轻量云（CentOS 7 + Docker：Jenkins / MySQL / 禅道） |
| 数据库访问 | SSH 隧道（`127.0.0.1:13306` → 服务器 MySQL） |
| 缺陷管理 | 禅道（用例库 + Bug 全生命周期） |
| 报告 | Allure 2.x（本地生成 + CI 生成双通道） |

> 环境说明：功能测试直接在生产环境执行——无独立测试环境，破坏性用例（删除等）执行后立即恢复数据，且全程使用专用测试账号，不影响真实用户。

## 六、风险与应对

| 风险 | 可能性 | 应对方案 |
|------|:------:|---------|
| 系统缺陷过多，功能测试时间不够 | 中 | 优先保证 P0 模块全覆盖，P1 至少覆盖正向用例 |
| 测试数据被污染 | 低 | 每次测试前备份数据库；专用测试账号 |
| 测试环境不稳定 | 低 | 及时记录环境问题并纳入报告 |
| 服务器内存不足以支撑 UI 全自动 CI | 高 | 实测数据决策（方案C：接口 CI 全自动 + UI 本地一键），服务器扩容后升级 |
| 报告外链不可用 | 中 | 对象层（COS）+ 浏览器层（nginx 托管）双通道验证 |
