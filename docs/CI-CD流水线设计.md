## 一、设计目标

1. **接口测试 CI 全自动**：代码变更自动触发回归（Poll SCM 30 分钟）；
2. **UI 测试流水线化**：Jenkinsfile 声明式 Pipeline 提供服务器手动触发与夜间报告发布入口（方案C：UI 全量仍本地跑）；
3. **报告闭环**：Allure 报告自动生成 → 上传腾讯云 COS 归档 → nginx 托管外网访问；
4. **质量看板**：失败自动邮件通知 + 定时构建（夜间）产出每日报告。

## 二、架构总览

```
┌─ 接口测试（轻量）──────────────────────────────┐
│  Jenkins lostfound-api-test（Poll SCM 30min）  │
│  pytest 55 条 → Allure → 报告归档              │
├─ UI 测试（重量级）─────────────────────────────┤
│  本地：run_ui_tests.bat 一键（21 条 ~155s）     │
│  服务器：Jenkinsfile Pipeline（report-only 默认 │
│          / 冒烟 / 全量 三档参数化）             │
├─ 报告发布 ────────────────────────────────────┤
│  Allure generate → COS 上传（--prune 幂等）     │
│  → 服务器 nginx /r/ 托管 → 外网可访问           │
└──────────────────────────────────────────────┘
```

## 三、Jenkinsfile 设计（声明式 Pipeline）

| 阶段 | 作用 |
|------|------|
| Checkout | 从 Gitee/GitHub 拉取代码（双远程，任一路径） |
| Env Guard | 校验必填环境变量（fail-fast，缺失即失败不浪费时间） |
| Setup | venv 缓存 + 依赖安装 + Chromium 内核（缓存加速） |
| UI Tests | 参数化可选：默认跳过（report-only）/ 冒烟 / 全量 |
| Generate Report | 容器内 Allure CLI 生成报告 |
| Upload to COS | `--prune --verify` 上传 + 复核（孤儿对象清理） |
| post | 成功/失败/总是：失败邮件通知（email-ext） |

**关键参数：**

| 参数 | 默认 | 说明 |
|------|------|------|
| `UI_TESTS` | false | true 时执行 UI 测试（report-only 弹性入口） |
| `TEST_PATH` | 空 | 冒烟可限定 `testcases/test_login_ui.py` |
| `REPORT_PREFIX` | latest | latest / build-N 归档前缀 |

**定时构建**：`cron('H 18 * * *')` = UTC 18:00 = **北京时间 02:00**（容器时区为 UTC，实测确认；凌晨避开资源高峰，产出每日报告）。

**凭据与安全**：COS 密钥走 Jenkins Credentials（Secret text，日志自动掩码）；桶名/域名/账号走全局环境变量；Jenkinsfile 零硬编码、纯 ASCII 注释、零真实值。

## 四、报告发布与访问

| 通道 | 机制 | 用途 |
|------|------|------|
| COS 归档 | 上传 `reports/latest`（覆盖）+ `reports/build-N`（历史，保留 10 个） | 对象层归档与历史管理 |
| nginx 托管 | `location /r/`（前缀匹配优先于 SPA fallback）→ `/www/wwwroot/report/` | **浏览器层外网访问**：`https://<被测系统域名>/r/`（流量走服务器免费包，零新增成本） |
| 更新机制 | 本地/CI 上传 COS 归档 + scp 同步服务器报告目录 | 双通道互备 |

**孤儿对象治理**：Allure 附件为随机 UUID 文件名，`put_object` 只增不删会造成孤儿堆积（实测残留 40 个）——上传脚本内置 `--prune`（dry-run 演练 → 真删 → 复核 74=74 OK），幂等可重跑。

## 五、实测数据（2026-08-24 服务器端到端）

| 构建 | 结果 |
|------|------|
| build #1 | 骨架全绿（report-only 按 when 条件跳过 UI 测试） |
| build #3 | 冒烟 **5 passed in 18.64s**（容器内存 768→1024MiB 后 OOM 解除） |
| build #4 | 报告生成 + 上传复核 **44 = 44 OK**（`--prune` 清理 160 个历史孤儿） |
| **端到端** | 拉码 → 依赖 → 测试 → 报告 → 上传 ≈ **30s** 闭环 |

**OOM 定位实证**：768MiB 容器内跑浏览器（哪怕单用例）触发 cgroup 杀进程（内核日志 `Memory cgroup out of memory: Killed process (java)`，RestartCount=1）；`docker update --memory 1024m` 放大后冒烟可跑——"资源边界用实测数据说话"。

## 六、已知环境限制与演进路径

| 限制 | 现状 | 演进路径 |
|------|------|---------|
| UI 全量不进服务器 CI | 4G 服务器内存约束（实测 758→689MiB） | 服务器扩容 ≥8G 后升级方案A：全量 UI 进 Pipeline |
| 容器时区 UTC | cron 按容器时区执行 | 改容器时区需同步调整 cron 表达式 |
| 邮件通知 | SMTP 未最终配通（网络层已通 587，认证配置中） | 配通后失败邮件自动送达，验证见部署清单 |
